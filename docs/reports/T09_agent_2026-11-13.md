## 4. 해석 결정 (기록)

1. **정책 표 literal 구현**: 프로파일 쌍 (REVIEW, OK)는 "불일치 → REVIEW"로 처리한다. 품질 교정 후 OK를 근거로 REVIEW를 OK로 구제하는 경로는 두지 않는다(낙관적 OK 금지 원칙). 설계 표에 구제 예외가 명시돼 있지 않아 보수적으로 해석했으며, 이 측정에서는 교정 경로 발동 0건이라 결과에 영향이 없다. 구제 해석을 채택하려면 설계 개정과 사용자 승인이 필요하다.
2. **종료 도구 예산 의미**: `escalate_review`/`stop`은 에피소드를 끝내는 전이로 기록하며 작업 예산을 소모하지 않는다. 작업 도구(`run_profile`/`inspect_artifact`/`compare`)만 행동 예산(3회)을 소모한다. 설계의 "행동 3회"는 검사 작업 예산으로 해석했다.
3. **승격 실패는 계약 실패가 아님**: T09 통과 기준은 메커니즘(거부·결정론·판정 소유·분모)이며 전부 PASS. 승격 검사는 별도 비교 축이고, 미충족 시 고정 모드 유지가 설계가 정한 정상 귀결이다.
4. **관찰**: review 47건이 전부 경계/다중약후보 유형이라 이 부분집합에서 에이전트가 줄일 수 있는 review가 구조적으로 없었다. REVIEW→NG 전환(교정 프로파일이 강한 결함 발견)도 0건. 승격 기준(review −5pp) 달성 가능성은 향후 부분집합/설계 개정에서 별도로 검토할 사항이다.
